# P2 — مساحة الاحتياج اليدوي بتصميم PRISM

هذه أول شريحة دمج للتصميم في التطبيق القائم، وليست إعادة تصميم جميع الصفحات أو تفعيل فهرس السنة. الأساس المنشور هو `2e26e26b7203da03016db206ddca1e93091b00fc` في #260. عقد الفهرس التحضيري في `P3-A-ANNUAL-CATALOG-CONTRACT.md` مستقل عن خدمة البحث الحالية.

## المشكلة والنتيجة

المراجع المعتمدة تعتمد البلاتيني والحبري والكوبالت مع Changa وNoto Sans Arabic وSora. التطبيق الحالي يفعّل تصميم molecular بألوان وخطوط مختلفة، لذلك لم يكن تغيير ترتيب العناصر كافيًا لتحقيق الهوية المقصودة.

تضيف الشريحة `PrismWorkspace` و`PrismMaterialIdentity` وطبقة CSS محصورة في مساحة الاحتياج. تستخدم رحلة `ManualNeedsJourney` وخدماتها الموجودة داخل تبويب الاحتياج في مركز المخزون. تبقى بوابة التفعيل والأهلية كما هي. لا تتغير علامة التصميم العالمية، أو المسارات أو شريط التنقل أو الصفحات الأخرى.

أصبح سياق السنة والحزمة مختصرًا، ونموذج إضافة الحزمة في تفاصيل ثانوية مع بقاء محتواه مركبًا. تعرض المساحة قائمة المواد ومحرر البند بجانب بعضهما عندما يتسع المحتوى، وتتراص على الهاتف. الاختيار المؤقت مميز عن سجل البنود المحفوظة؛ إزالة اختيار لا تلغي بندًا. اسم البحث «مادة مسجلة» يصف مصدره الحالي، ولا يوهم بعضوية مؤكدة في فهرس 2026.

تظهر رسالة السجل الفارغ خارج الجدول لتبقى كاملة على الهاتف، بينما يحتفظ السجل الذي يحوي بنودًا بجدوله القابل للتمرير. وعند ضيق مساحة المحتوى توضع الوحدة وزر اختيار المادة في سطر مستقل لإتاحة عرض الكمية والهوية بوضوح.

الأكواد والأسماء ذات الاتجاه المختلف معزولة بعناصر HTML دلالية، وتستخدم القواعد أبعادًا وحواف منطقية. يشتمل المظهر الداكن على الحقول والرسائل والجداول والتركيز. حركة التحميل محدودة وتُوقف عند تفضيل تقليل الحركة. لا تستعمل الصور أو الأيقونات لإثبات المخزون أو الهوية القانونية.

## إصلاحات التفاعل المرتبطة بالشريحة

| الحالة | التغيير |
|---|---|
| تصحيح أو إلغاء بند بعد إعادة الدخول | اسم المادة ورمزها من الهوية المحملة للبند، حتى إن كانت قائمة الاختيار المؤقت فارغة؛ ينتقل التركيز إلى حقل الإجراء |
| تبديل لغة النموذج | تبقى أسماء المصدر الثنائية خامًا ويجري توطينها عند العرض؛ لا يعاد تحميل نطاق العمل أو مسح الكمية أو نية الحفظ بسبب اللغة |
| تغيير المادة أو المستفيد صراحة | تُمسح الكمية والسبب ومفتاح النية غير المرسلة مع تنبيه؛ لا تنتقل كمية هدف سابق إلى هدف جديد |
| إزالة المادة المفتوحة من الاختيار | يفرغ هدف الإدخال وحقوله غير المحفوظة؛ لا يستدعى كاتب كمية أو أمر إلغاء لسجل محفوظ |
| كتابة جارية أو نتيجة غير محسومة | يثبت payload ومفتاح النية، وتقفل أدوات تغيير السياق داخل الرحلة؛ تبقى إعادة الطلب نفسها متاحة بعد انقطاع الاتصال |
| انقطاع Supabase المغلف | `central_needs_request_failed` بلا SQLSTATE لا يُعامل كرفض قاعدة نهائي؛ يعاد استعمال المفتاح والكمية والسبب نفسيها |
| جاهزية قرئت قبل بدء كتابة | تُبطل الجاهزية وتأكيد الإرسال السابقان؛ لا يبقى إجراء تقديم مبني على قراءة أقدم |
| فشل قراءة البنود | إعادة قراءة صريحة بحالة تحميل؛ لا يعرض السجل القديم كأنه أحدث قراءة، ولا تقول الرسالة إن كتابة سابقة لم تقع |
| اختلاف قدرات الاعتماد | صياغة القرار محايدة؛ شروط الخادم الحالية، ومنها M232، تبقى صاحبة القرار |

قفل السياق محلي لهذه الرحلة. لا يمثل مسودة دائمة أو مصالحة لعملية بعد إغلاق المتصفح، ولا يحرس وحده تبديل المؤسسة من القشرة العامة أو تسجيل الخروج. إعادة المحاولة الصريحة تستخدم idempotency القائم؛ لم يضف هذا الفرق كاتبًا أو إعادة تلقائية أو نتيجة نجاح متفائلة.

يبقى parser الكمية النصي كما هو، بما فيه الصفر والفراغ والدقة. المدخل العربي/الفارسي ما زال يعرض اقتراح ASCII عبر العقد الحالي؛ دعم التحويل الصريح الميسر لاحقًا لا يجيز تعديل الرموز الوطنية أو التقريب إلى JavaScript Number.

## الخطوط والتراخيص

Noto Sans Arabic يستعمل dependency الموجودة `@fontsource-variable/noto-sans-arabic@5.2.10` وترافقه رخصته. لا تغيير لـpackage.json أو lockfile، ولا طلب خط من CDN أثناء استخدام الواجهة.

- [Sora: مصدر الخط وترخيصه](https://github.com/sora-xor/sora-font).

## التحقق وإعادة الإنتاج

اختبارات الرحلة والبنود والـpicker تستخدم المكونات الحقيقية وحدود خدمة مضبوطة. تشمل التصحيح من جلسة جديدة، اختيار عدة مواد، الطلب المتأخر، النقل بين الأهداف، خطأ fetch المغلف، حفظ المفتاح والكمية، اللغة أثناء الكتابة، وإعادة القراءة. اختبارات P3-A0 مستقلة وتغطي العقد والمحول فقط.

`tests/prism-needs.visual.test.ts` يشغّل المكون الحقيقي مع **سلسلة CSS وخطوط التطبيق نفسها**، وعلامات molecular القائمة، وخدمات تجريبية صريحة في `tests/browser/`. تشمل مصفوفته العربية/الإنجليزية، الفاتح/الداكن، وعروض 1366 و1024 و390 و320، وحالات الفراغ والفشل والقراءة فقط والطلب المعلق. يتحقق من overflow والتركيز والأحجام والخطوط المحسوبة فعليًا؛ مجرد تحميل ملف الخط لا يكفي. يفشل الاختبار عند طلب شبكة خارجي أو خطأ متصفح.

لتشغيله محليًا في Node 22 مع Chromium مثبت:

```sh
MEDISTOCK_PRISM_VISUAL=1 PRISM_CHROMIUM_PATH=/absolute/path/to/chromium \
  npx vitest run tests/prism-needs.visual.test.ts
```

المعاينة التجريبية لا تختبر Auth أو PostgREST أو RLS أو SQL أو حفظًا فعليًا. حارس `qa-harness-production-safety.test.ts` يبني الإنتاج مع علم QA ويمنع تسرب معرفات هذه المعاينة أو خدمتها الوهمية إلى bundle. لقطات الفحص أدلة محلية للمراجعة، وليست واجهة بديلة منشورة.

سجل القبول المؤرخ في الذاكرة الحاكمة يثبت الرأس وأعداد النتائج الفعلية. يحتفظ بالفشل الأول وأسباب التصحيح، بما فيها تجاوز رسائل الهاتف وCSS الذي غلب خط الكمية قبل إصلاحه. لا تنسب نتيجة CI الخاصة بـ#260 إلى هذه الشريحة دون تشغيل مستقل للرأس الجديد.

## حدود التسليم والخطوة التالية

لم تتغير migrations أو مرشحات SQL أو خدمات الأعمال أو RLS أو المخزون أو dependencies. لا حذف صفحة ولا نقل تاريخ، ولا تفعيل ميزة في بيئة مستضافة. رجوع هذه الشريحة هو رجوع commit العرض ضمن مسار الإصدار القائم، دون تغيير تاريخ قاعدة البيانات.

الخطوة التالية للفهرس هي P3-A1: سجل سنة وعضوية ونسخ حقول وحراس خادمية، ثم البحث السنوي والإضافة الصريحة وقراءة النتيجة. بعدها يربط P3-B البند بنسخته السنوية عبر الكاتب الموجود. تعميم PRISM والتقاعد المشروط لبقية المداخل يتبع قبول كل وظيفة وسجلها وصلاحياتها؛ لا تُحذف صفحة الاحتياج التاريخية بمجرد اكتمال هذه المساحة.

# C3 caller-scoped original reader

`api/_c3-core/original-reader.ts` adapts the existing private `annual-c3-authorized-source.ts` reader from #266, preserving its source history through cherry-picks. The duplicate reader initially developed in this branch has been replaced. Its caller must be authenticated through the existing server helper. The reused reader checks current annual authority, the exact C2 capability and the caller-scoped download, then verifies metadata/base64/hash. It never constructs a service client or accepts browser bytes, source cells, hashes or a filename.

The bridge snapshots the requested scope, validates the returned scope/original identity, 3 MiB size ceiling, canonical base64 and safe C2 first filename, and independently hashes the bytes. It returns the narrow C3 source envelope. Renamed uploads remain separate C2 history; this bridge identifies the retained original by its first filename. Transport and authority failures are closed, bounded errors, without backend details or automatic retries.

Synthetic transport tests and a real XLSX parser integration verify this boundary. They do not constitute real Auth acceptance, a persisted extraction attestation, template approval or legal catalog/quantity approval. No endpoint, SQL, original workbook or real template is added by this increment. The existing #266 proposal chooses read-only, paged, on-demand C3 evidence. Enforceable worker termination, the authenticated HTTP boundary and non-Production target activation remain required before exposing computation. A subsequent catalog writer must independently reverify source evidence; a new C3 SQL store is not introduced merely to complete a read-only path.

`preparation.ts` connects this read bridge to the accepted extraction core. An explicitly reviewed registration binds both the template and the entire workbook sheet inventory. A single-sheet template cannot silently claim a workbook with additional unreviewed sheets. Recognition checks exact sheet names/indices, physical headers and classification anchors; it never selects by filename. The core then independently reparses the candidate. Multiple matching registrations remain held, even when one appears more comprehensive. Registry and registration hashes bind the shape decision separately from the core template identity.

The internal projection is bounded to 10,000 actual row slots, 100,000 declared row iterations across all blocks, and 2 MiB serialized candidate evidence. Excessive overlap or output is held without truncation. These are internal computation bounds, not an HTTP page allowance. `persisted: false` is explicit. The service is not reachable from HTTP, does not write a year catalog and cannot approve an annual quantity.

The reused #266 worker boundary now waits for termination before completing. The new compiled entry uses the accepted extraction core and explicit whole-workbook registration; it does not import the earlier alternative annual replay engine. It returns at most 50 rows and 256 KiB per page, with at most 5,000 total candidate rows. Cursor identity binds owner/year/original bytes, reviewed registration and the full pinned parser identity. The registration digest includes workbook coverage; the core template digest remains separately labelled. Malformed or extension/content-mismatched source is held without modifying the shared parser. No source quantity column is projected.

Native tests compile the actual worker, parse synthetic XLS/XLSX/CSV, verify stable pages and source-bound cursors, refuse additional sheets/corruption/renamed CSV, and prove a synchronous busy loop actually exits at its deadline. Synthetic unit tests are separate from real Auth. The CI continuation signs in through real Auth, calls the actual server authenticate helper and C2 RPCs, then compiles/runs the same worker against a synthetic retained original. It tests anonymous/cross-owner refusal, current permission revocation and no catalog/quantity/stock/audit side effects from reading. That step is not accepted until its actual current-source run passes.

Hosted worker packaging, the HTTP route, non-Production target activation and employee evidence UI remain open. The CI-built worker proves execution in the disposable runner, not Vercel asset tracing or hosted Worker support. Hosted SQL compatibility inherits the explicitly documented platform-read HOLD; no hosted role access is changed.

# R20 — معاينة نقل هويات المواد للسنوات الجديدة (2026 → 2027)

**الحالة: تنفيذ نواة فحص غير نافذة؛ لا تطبيق قاعدة بيانات ولا تفعيل واجهة.** هذا المسار موازي ومستقل عن #287/#290/#293 ولا يحرر ملفاتها أو يبدّل SQL أو يغيّر نظام التحكم بالوصول.

## القرار الحاكم

- بعد فتح/تهيئة السنة الجديدة صراحة بواسطة موظف مخوّل، يؤخذ أحدث **سنة سابقة معتمدة قانونيًا** لنفس الجهة المالكة. صفة السنة `active` أو `archived` وحدها ليست دليل اعتماد.
- تُنقل **هوية المادة فقط** (الاسم العلمي/العربي، الرمز الوطني النصي، الشكل، التركيز، الوحدة، الباركود إذا ثبت) والتصنيفات الأصلية **مع مراجع المصدر**؛ لا تُنقل كميات الاحتياج أو التحصيص أو المخزون أو حالات الاعتماد.
- قبل إعداد قائمة النقل يفحص النظام اكتمال تعداد سنوات المصدر ومواد السنة المختارة ومواد السنة الهدف. لا تخمين عند انقطاع التصفح أو الرجوع إلى سنة/جهة أخرى.
- يقارن كل بند مع النسخة القانونية الحالية ونسخة حقوله في المصدر، ويرفض النقل الصامت إن كان مصدر المادة متقاعدًا أو غير قابل للاختيار، أو تغيرت البصمة القانونية، أو اختلف رقم النسخة، أو غابت وحدة/رمز/اسم إلزامي، أو لم يثبت التصنيف الأصلي.
- التكرار في مصدر السنة أو في هدفها يُظهر حالة HELD. لا يأخذ «أول» مادة متشابهة ولا يحول الرمز الوطني إلى رقم يفقد الأصفار.
- النتيجة `PREVIEW_ONLY` لا تحمل مفاتيح تخويل ولا تكتب سجلات. الكاتب المستقبلي يراجع الأدلة والصلاحيات والبصمات والسنة تحت قفل مع معاملات ذرية، ويسجل من نقل المادة ومتى ومن أي نسخة، مع منع النقل المتكرر أو التزامن المزدوج.

## أنجزت هذه الدفعة

- `src/features/central-needs/annual-catalog/annual-year-rollover-preview.ts`: دالة خالصة بلا استعلامات أو كتابة؛ مخرجات جاهزة/معلقة ورفض واضح للمراجع الناقصة.
- `src/features/central-needs/annual-catalog/__tests__/annual-year-rollover-preview.test.ts`: 14 حالة تضم 2026→2027 و2027→2028 وعزل الجهات والسنوات، الأقسام الأصلية، الأصفار الأولى للرمز الوطني، البصمة والنسخة والتقاعد والتكرار.
- اختبارات محلية على Node 22 مع حواجز نسخ أنواع تحاكي العقد الحقيقي؛ `tsc --strict` ناجح و14/14 حالة ناجحة. الاختبارات على **شيفرة المستودع الكاملة** وCI مستحقة على رأس PR المنشور، ولا يدّعي الاختبار المحلي قبول SQL أو E2E.

## بوابة الدمج/التفعيل التالية

1. مصالحة العقد مع مرشحات P3-A1 وP3-B وC4 غير المطبقة، خصوصًا ارتباط التصنيف بالشواهد والاعتماد القانوني للسنة.
2. إنشاء كاتب PostgreSQL مستقل بمخازن سند النسخة/التصنيف، من دون التلاعب بالمصادر التاريخية أو نسخ احتياج/تحصيص/تجهيز، مع RLS وضبط EXECUTE واختبارات تزامن وفشل وتراجع وقراءة الهدف.
3. تكامل واجهة تهيئة السنة، مع صفوف `HELD` ونقل الهوية على دفعة محدودة، وإمكانية إضافة مادة جديدة من المسار القانوني الحالي.
4. إثبات القبول في بيئة Staging معزولة بعد توافق مخططها، ثم تفويض مستقل قبل SQL Production أو الأدوار. لا تصف ميزة السنة الجديدة أنها تعمل في Production قبل ذلك.

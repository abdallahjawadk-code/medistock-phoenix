# P3-C3 — annual original extraction core, bounded first slice

The governing r14 §27.6 requires trusted extraction from retained C2 original bytes, a reviewed versioned template, physical cell/classification evidence, missing/conflict states and evaluation on files not used to prepare that template. C2 `server_received_original` remains a receipt of bytes; C1/A1 `client_attested` evidence retains its existing meaning.

`annual-extraction-core.ts` provides Node-only computation for a future trusted adapter. The caller supplies an independently authorized owner/year/original reference with its exact bytes and a registry loaded from reviewed server definitions. The engine snapshots definitions and original bytes, independently checks byte count/SHA-256, reparses through the existing pinned CN-2A Node adapter, binds exact physical headers and emits only mapped identity occurrences plus validated physical source-classification witnesses. A definition fingerprint identifies the exact registered definition bytes; it is not a signature or authorization proof.

Unknown template identity/version, rejected parsing, changed mapped headers and classification conflicts remain held. Missing/numeric/formula identity fields keep the existing evidence states. No fuzzy identity, unit alias, inferred replacement code, quantity, beneficiary or permanent learning is added. Proposed classifications remain proposed and cannot acquire a source witness through their label alone.

The result is explicitly an `annual_identity_extraction_candidate`. This helper does not authenticate a caller, prove that input metadata came from C2, persist an extraction, promote client evidence, approve a legal identity or expose an endpoint. A forged browser receipt cannot become a trusted record by calling this function. No operational UI, database change, hosted activation or real reviewed template is included.

Local original-corpus evaluation has a separate `local_corpus_review` origin, a literal non-organization review namespace and a content-addressed `corpus:` reference. It never invents C2 UUIDs, uses synthetic application entities or claims a server receipt. The candidate retains this origin; a future persistence adapter must accept only an independently reloaded canonical C2 original and must never promote a local review candidate by copying its metadata.

The next adapter must authenticate and re-check current scope through the established annual authority, load the canonical C2 original itself, choose only a registered reviewed definition, persist immutable parser/template/source/witness identity atomically and reconcile exact retries. It must define capability discovery, permissions, audit and concurrent activation before SQL or an endpoint is accepted. Preserve the original C2 receipt, prior contracts and all source values. Template review must use actual supplied originals and an independent held-out corpus; synthetic unit fixtures establish computation behavior only.

Validation for this slice uses real synthetic XLSX bytes, including a separate held-out synthetic file, altered headers/classification, exact code text, missing fields, excluded quantities/institution cells, hash/size/scope refusal and definition mutation isolation. It does not establish real-corpus accuracy or Production readiness.

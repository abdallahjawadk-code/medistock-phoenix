The actual annual-entry browser journey opened a year and plan but had no beneficiary choices. The general organization directory correctly enforces own-organization RLS for this non-super-admin caller. Filtering that directory to care institutions yields an empty list. Existing M226 manual-need authority permits active, unarchived care institutions; it does not require an invented parent-PDA relationship.

The new VOLATILE SECURITY DEFINER reader first applies the unchanged owner/HOME-PDA `central_needs.view` guard and existing capability seal, then returns only `id/name/nameAr` for the existing eligible set. It has bounded 50-row UUID-keyset pages and a 256-KiB response ceiling. Anonymous, service and foreign-owner callers receive no new authority. General directory policies, role memberships and all old function definitions/ACLs stay unchanged. No quantity, policy, canonical, stock or audit writer is added.

After a verified annual contract, the journey uses this reader independently of catalog preparation. It discards superseded directory/annual responses. Failure is explicit; it does not silently return partial pages or use the old directory. Legacy journeys retain their existing list. The client validates scope, exact public fields, order and cursors, and refuses more than 200 pages instead of displaying a truncated list.

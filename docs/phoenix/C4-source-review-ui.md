# C4 employee source review — implementation awaiting browser acceptance

The original-file history opens a scoped review of the first saved filename, ID, byte size and SHA. The employee explicitly chooses a reviewed profile, reads a bounded C3 page with original witnesses, selects reviewable rows, previews an existing canonical material and gives a reason before submitting the accepted C4 intent. Empty registries and held evidence cannot create membership. This panel creates neither canonical materials nor annual quantities.

A pending write locks the surrounding scope. An ambiguous acknowledgement keeps the exact intent and request ID; the employee can read its receipt and, only after a missing/prepared receipt, explicitly retry that intent. A committed receipt must be followed by a fresh annual-item read. Failure of that read offers only a read retry. Closing returns focus to the originating history button. The accepted server remains authoritative for scope, evidence, canonical matching, current permission and trusted employee snapshots.

Local verification: 53 tests across source review/policy, original-file UI and annual journey; focused types and lint passed. A StrictMode discovery race and an already-open registration escaping the review lock were reproduced before their fixes. Registration, existing addition and editor controls now share the review lock. Arabic/English, empty registry, immutable retry and receipt recovery have component coverage. Opening and closing focus are asserted; actual keyboard activation still requires browser verification. Completed selections are cleared after the current read so a successful membership cannot be submitted again from the stale form.

`c4-source-ui.mjs` and its loopback-only proxy exercise the actual workspace and actual C2/C3/C4 handlers with a fresh synthetic owner and an explicit reviewed synthetic profile. They cover 16 language/theme/width combinations, keyboard opening/confirmation/receipt/closing, and a successful commit whose acknowledgement is replaced by an unknown 503. Recovery must read the receipt and current annual item, with one commit POST and no quantity/stock change. These browser assertions have not yet passed; this document does not mark the UI accepted. No Production registry activation, SQL application, hosted role change or real 2026 workbook is included.
